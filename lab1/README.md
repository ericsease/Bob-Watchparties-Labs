### Path 2: Bring Your Own Project

Have something specific in mind? Great! Here's how to make the most of your time:

#### Best Practices for PoC-Length Projects

**1. Keep Scope Small and Focused**
- Choose ONE core feature to implement
- Aim for a working prototype, not a production app
- You can always expand later

**2. Define Clear Success Criteria**
Before you start, write down:
- What does "done" look like?
- What's the minimum viable version?
- What can you skip for now?

**Example:**
```
✅ Success: A working todo app where I can add and delete items
❌ Not needed yet: User authentication, categories, due dates
```

**3. Break Down Into 30-Minute Chunks**
Structure your time:
- **0-10 min**: Planning and setup
- **10-30 min**: Core feature implementation
- **30-40 min**: Testing and refinement
- **40-45 min**: Documentation and wrap-up

**4. Use Bob's Modes Effectively**

**Start with Plan Mode (📝):**
```
I want to build [your project]. Help me:
1. Define the project structure
2. Identify the key components
3. Plan the implementation steps
4. Recommend the tech stack
```

**Switch to Code Mode (💻) for implementation:**
```
Based on our plan, let's implement [specific feature].
Create the necessary files and code.
```

**Use Ask Mode (❓) when stuck:**
```
I'm getting this error: [error message]
What does it mean and how do I fix it?
```

**5. Iterate Quickly with Auto-Approvals**
- Enable auto-approvals for rapid file creation
- Review generated code after each step
- Make adjustments as you go

**6. Document as You Go**
Ask Bob to:
- Add comments explaining complex logic
- Create a README for your project
- Document any setup steps needed

## Getting Started

### Step 1: Choose Your Project
Decide whether you'll:
- Build one of the suggested projects above, OR
- Work on your own idea

### Step 2: Set Up Your Workspace
```bash
# Create a new directory for your project
mkdir lab1-my-project
cd lab1-my-project
```

### Step 3: Start with Planning
Open Bob and switch to **Plan Mode (📝)**

Use this template prompt:
```
I want to build [describe your project in 1-2 sentences].

The key features are:
- [Feature 1]
- [Feature 2]
- [Feature 3]

I have about 30-45 minutes. Help me:
1. Scope this appropriately for the time available
2. Plan the project structure
3. Identify what to build first
4. Recommend the simplest tech stack
```

### Step 4: Implement
Switch to **Code Mode (💻)** and start building!

**Pro tip:** Work on one feature at a time. Get it working before moving to the next.

### Step 5: Test and Refine
- Test your project thoroughly
- Fix any bugs you find
- Add polish if time permits

### Step 6: Document
Ask Bob to help you create:
- A README explaining what you built
- Comments in your code
- Instructions for running the project

## Example Workflow

Here's a complete example of building a simple project:

### Example: Building a Tip Calculator

**1. Planning (Plan Mode):**
```
I want to build a tip calculator web app. Users should be able to:
- Enter a bill amount
- Select a tip percentage (15%, 18%, 20%, custom)
- See the tip amount and total
- Split the bill among multiple people

I have 30-45 minutes. Help me plan this.
```

**2. Implementation (Code Mode):**
```
Create the tip calculator with:
- index.html with a clean form layout
- styles.css with modern, mobile-friendly design
- app.js with calculation logic
Make it work without any backend.
```

**3. Enhancement (Code Mode):**
```
Add these improvements:
- Validate that inputs are positive numbers
- Format currency properly
- Add a "Clear" button
- Make it responsive for mobile
```

**4. Documentation (Code Mode):**
```
Create a README.md that explains:
- What the calculator does
- How to use it
- How to run it locally
```

## Tips for Success

### 🎯 Stay Focused
- Resist the urge to add "just one more feature"
- Get the core working first
- Polish only if time permits

### 💬 Communicate Clearly with Bob
- Be specific about what you want
- Provide context and constraints
- Ask for explanations when needed

### 🔄 Iterate Quickly
- Build → Test → Refine → Repeat
- Don't aim for perfection on the first try
- Small improvements add up

### 📚 Learn as You Go
- Ask Bob to explain unfamiliar concepts
- Request comments in the code
- Use Ask Mode liberally

### 🎉 Have Fun!
- This is your chance to explore
- Try something new
- Experiment with Bob's capabilities

## Common Pitfalls to Avoid

❌ **Scope Creep**: Starting simple and adding too many features  
✅ **Solution**: Write down your MVP and stick to it

❌ **Analysis Paralysis**: Spending too long planning  
✅ **Solution**: Plan for 5-10 minutes max, then start building

❌ **Perfectionism**: Trying to make everything perfect  
✅ **Solution**: Aim for "working" first, "polished" second

❌ **Not Testing**: Building everything before testing anything  
✅ **Solution**: Test each feature as you build it

## Troubleshooting

### "I don't know what to build"
- Pick one of the suggested projects above
- Think of a small problem you have and solve it
- Recreate a simple app you use daily

### "My project is too complex for 45 minutes"
- Cut features until it fits
- Focus on the absolute core functionality
- Save enhancements for later

### "I'm stuck on an error"
- Switch to Ask Mode and paste the error
- Ask Bob to explain what's wrong
- Request step-by-step debugging help

### "Bob's code isn't working"
- Test in small pieces
- Ask Bob to add error handling
- Request debugging suggestions
